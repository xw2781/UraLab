# Release 1.5.0

Released on 2026-09-08.

## User-Facing Changes

### Features
- **dataset**: The Data tab's right-click menu has a Clear data command that sets every cell of a hand-entered dataset to 0.
  - It shows only while the grid is editable, beside Paste.
  - Once every cell is 0 the Origin Length, Development Length, and Stored at controls open up, as they do for a new dataset.
- **dataset**: The Data tab now shows a "Stored at" value beside Origin Length and Development Length, and an empty hand-entered dataset can be told there to keep its figures at a finer period than it is shown at.
  - The pair reads the way ResQ's own Edit Triangle dialog puts it: the period the dataset is shown at, and beside it the period its file is really kept at.
  - The origin "Stored at" is a dimmed readout, because the Origin Length control is what fixes it while the dataset is empty, exactly as in ResQ.
  - The development "Stored at" can be lowered while the dataset still holds nothing but blanks and zeros, so a triangle shown a year at a time can be kept month by month underneath. Lowering it leaves the grid on screen unchanged; the next save writes the finer file.
  - Once the dataset holds figures the control is dimmed and says why, and changing the length on screen while it is still empty moves the stored period with it, as ResQ does.
  - The hint that used to say a first save would fix the period is gone: the new value beside each control says it instead.
- **project settings**: Import Data now offers an Import Scope step to choose which datasets and reserving class types the import refreshes.
  - The step opens on the scope used by the project's last import, whoever ran it, and says who chose it and when.
  - Untick datasets or reserving class types to leave them as they are; a whole-project import clears any earlier narrowing.
  - Reserving class types are grouped by level, and a class is refreshed when it matches a ticked type at every narrowed level.
  - Each list has its own filter box and group tick boxes with counts.

### Improvements
- **dataset**: A hand-entered triangle can now be typed into, pasted into, and linked while it is shown a year at a time over finer figures.
  - Only a view that groups the rows is still read-only, and its message now names that one control: set the Origin Length back to edit.
  - While the columns are grouped, the status line says in one line that a save writes each figure at its own column date and clears the periods between.
  - A vector keeps the wording it already had, because it has no columns to group.
- **dataset**: Adding or refreshing a large Excel-linked range in the Data tab is now close to instant instead of taking minutes.
  - A linked block of 120 by 120 cells used to be read one cell at a time, re-reading the whole worksheet for each; the sheet is now read once for the whole block.
  - Reading a linked workbook no longer leaves the file locked, so it can still be saved and renamed in Excel.
- **dataset**: Reopening a dataset or changing the view it is shown at no longer re-reads every linked workbook; Excel is read only where a workbook was saved after the dataset.
  - Each linked workbook's timestamp is checked first, which is far cheaper than opening it.
  - A workbook that cannot be reached counts as unchanged, so an unavailable drive never blanks the figures on screen.
- **dataset**: The Origin Length and Development Length controls no longer show a hover hint about the stored period; the Stored at value beside each length says it.
- **dfm**: The DFM Details tab no longer shows a Stored at value beside Origin Length and Development Length; only the Dataset window does.
- **dfm**: A User Entry formula on the Ratios tab now reads an average row at the Decimal Places set on the Details tab, so the numbers on screen multiply out to the factor shown.
  - The Apply Growth and Cutoff Adjustments macro writes the plain average row name instead of wrapping it in a rounding function, and the notes it generates still reconcile.
  - Formulas written by the earlier version of the macro keep working and give the same value.
  - Changing Decimal Places now re-works the User Entry rows and the results that depend on them, not just how the numbers are printed.
- **project settings**: Saving Data Processing Rules now runs on ArcRho Server and shows its progress in a window, like Import Data.
  - The check of every generated dataset that follows a save runs next to the data instead of over the network drive, so a save that took minutes from a workstation now takes seconds.
  - A progress window opens when you press Apply and save, follows each step, and closes when the rules are saved.
  - Without a running ArcRho Engine the save still works the old way.
- **project settings**: Saving Data Processing Rules now refreshes the datasets the rules affect, and the methods built on them, without reopening each one.
  - After the rules are written, ArcRho Server rebuilds every generated dataset that reads an affected measure, reserving class by reserving class, and updates the methods that depend on them, the same way Import Data does.
  - The progress window names each reserving class as it is refreshed, and the status line reports how many datasets and methods were refreshed.
  - A dataset that could not be refreshed is named in the status line; the rules are still saved, and that dataset refreshes the next time it is opened.
  - Renaming or reordering rules saves at once: it changes no calculation, so no dataset is marked out of date or refreshed.

### Fixes
- **berquist sherman**: A Berquist-Sherman method can now use a generated dataset as its source, building the annual view it needs instead of refusing the method.
  - A generated dataset records how fine the project's source table is rather than the shape of its own cache, which used to be read as 'not an annual dataset'.
  - When no annual cache exists, it is produced from the source table the same way a development factor method produces one.
- **dataset**: A hand-entered dataset whose values were all set to 0 now keeps its zeros when a length is changed, and keeps the new lengths when values are pasted in and saved.
  - Changing a length used to reload the dataset's saved file over the zeros, and pasting values then snapped the length controls back to the file's stored period.
  - The grid is now rebuilt empty at the new lengths without a reload, the controls hold those lengths until the values are saved or set back to 0, and the save writes a new file at that shape in place of the old one.
- **dataset**: A coarser view of a finer triangle now adds up along the calendar diagonal instead of mixing valuation dates.
  - Opening a monthly or quarterly triangle at a coarser period built each annual cell from figures valued at up to twelve different dates, so every cell of the view was wrong.
  - A coarse cell whose parts are not all present is now blank rather than a partial sum, and a roll-up that cannot line up on one valuation date is refused with a plain reason.
- **dataset**: A triangle's column ages now come from Project Settings at every view, so a project valued in August reads 8m, 20m, 32m instead of the list its sidecar happened to carry.
  - The ages count back from the Development End Date and are cut to the columns the dataset has.
  - The sidecar's own list answers only when the project headers cannot be read at all.
- **dataset**: A linked dataset can now be shown and saved at other lengths than its links were entered at.
  - Saving a monthly dataset with a linked Excel range at a yearly view no longer fails with "This dataset's cells are linked. Set Origin Length to 1 and Development Length to 1 to save this dataset."
  - The dataset remembers the lengths its links were entered at apart from the lengths it is shown at, so the links wait at their own view and come back when the lengths do.
  - Refreshing links from Excel or from another dataset reads and writes them at the lengths they were entered at, whatever the dataset is shown at.
- **dataset**: A dataset entered at annual periods but held at finer ones is now read as the annual triangle it shows, so its calculated and Berquist-Sherman dependents refresh instead of coming back empty or refusing the dataset.
  - A formula that divides such a dataset by another one used to compare the finer grid against the coarser one and leave the result untouched or at zero.
  - A Berquist-Sherman method now decides 'annual' from the shape the dataset is shown at, the same test the page makes, and reads the annual view; a dataset shown at any other period is still refused.
- **dataset**: Switching a monthly linked dataset to a yearly view no longer reports every linked cell as broken.
  - A dataset whose Excel range was linked at monthly lengths could be recorded as linked at the yearly view it happened to be saved at, so changing the view opened an "Excel Link Reference Error" listing thousands of cells that are no longer part of this dataset.
  - The origin period the links belong to is now read from the period the dataset's own file is held at, which is the only one a link can be entered at, instead of from a display the file may have been saved at long afterwards.
- **dataset**: A dataset's links now belong to the display it was saved at, so a triangle stored monthly under a yearly view keeps its yearly links live.
  - A link names a cell of the grid that was on screen when it was written, not a cell of the file, so values can be typed and Excel ranges pasted at that view over a file stored finer.
  - Links are held still only while the length controls sit off the pair the links were written at: no contours, no link editing, no refresh.
  - The formula bar and the save refusal share one sentence naming the lengths to put back.
- **dataset**: A coarser view of a hand-entered triangle is now built from the figures you typed every time it is opened, instead of from a saved copy that never updated.
  - Opening a monthly or quarterly hand-entered triangle at a yearly view used to leave a yearly copy of it beside the file; every later yearly open served that copy, so an edit to the figures, including an Excel refresh, was never shown.
  - No such copy is written any more, and one left behind by an earlier version is ignored.
- **dataset**: A dataset opened from Project Instance now shows the Origin and Development Length it was saved with, even when its figures are stored finer underneath.
  - A hand-entered triangle imported from ResQ at a yearly display over monthly figures opened as 12/1 and could not be put back to 12/12, because the open reported the file's own shape as the displayed one.
  - The open now rolls the stored figures up to the saved display shape, shows the stored period beside each length, and keeps the coarse-view note on the status line.
- **dataset**: A coarser view of a triangle stored at a finer period is now valued on the project's Development End Date, so it keeps its latest diagonal and its figures.
  - A triangle imported from ResQ at a stored length of 1 month and shown at 12 months read the 12-, 24-, 36-month columns of the stored grid, which hold nothing in a project valued at August, and dropped the last column, so the view showed zeros and lost its latest diagonal.
  - The view now counts development periods back from the Development End Date the way ResQ does, reading 8, 20, 32, ... 116 months of age for an August valuation, and any development length you pick on the Data tab reshapes the stored figures the same way.
- **dataset**: A period chosen under "Stored at" is now kept when values are pasted in before the first save.
  - Setting a hand-entered triangle to keep its figures monthly under a yearly view, pasting a 10x10 block and saving once now stores it monthly, as ResQ does, instead of moving the store up to the yearly view.
  - The "Stored at" control now stays open until the dataset is saved with a value in it, rather than closing as soon as something is typed or pasted.
  - This matters when the dataset is sent back to ResQ, which can only show the right column ages for a triangle kept at the finer period.
- **dataset**: A triangle's cells now stop on the project's own calendar diagonal, so cells past the valuation date can no longer be typed into.
  - A new or cleared hand-entered triangle asks the project where its diagonal falls instead of dropping one column a row, which was only ever right when the origin and development lengths matched.
  - An annual triangle shown at a quarterly development now drops four columns a row and stops at the valuation date rather than at the last development header.
  - A figure an older file holds past the diagonal is no longer shown or editable, and the next save writes that cell blank. Vectors keep every cell.
- **methods**: Bornhuetter Ferguson, Cape Cod, and Bootstrap now accept a precedent stored at a finer period than the method, instead of refusing it with 'uses 1-month origins; expected 12'.
  - A generated precedent, such as an exposure vector in a monthly project, is rebuilt at the method's own period, the way the DFM already does it.
  - A hand-entered precedent stored finer than the method is summed up to the method's period from the figures you typed.
  - A precedent stored coarser than the method is still refused, because yearly figures cannot be split into months.
- **resq import**: A dataset imported from ResQ now records how fine its figures really are, the way ResQ itself stores them, so a generated dataset in a monthly project shows 'stored 1' instead of 'stored 12'.
  - The import reads ResQ's own stored lengths for every dataset. A generated dataset is stamped with them, which is the shape the Engine can rebuild it at.
  - A hand-entered triangle or vector that ResQ shows yearly but stores monthly is now copied month by month, so the finer figures reach ArcRho and the yearly view is built from them.
  - Datasets imported before this change keep 'stored 12' until the class is imported again or the Engine rebuilds them.
- **result selection**: A Result Selection no longer fails with "Precedent refresh failed" over a development method whose ultimate did not move during the same refresh.
  - Saving a data processing rule regenerates datasets such as Total Earned Exposure, which claim-count development methods use only as their ratio basis. Those methods were recomputed to the same ultimate, yet every Current Qtr Indicated and Current Qtr Selected that loads them was refused and left flagged for review.
  - The refresh now tells the Result Selection step which development methods it already checked and found unchanged, so they count as current instead of as failed precedents.

### Breaking Changes
- **result selection**: The Sync button is gone from a Result Selection window; comparing one against its ResQ counterpart is now done only by the Sync Reserving Class with ResQ macro.
  - The button on the Result Selection tab bar, and the version-comparison window it opened, have been removed.
  - The macro already does the same comparison across a whole reserving class, in a form that reports what it found before anything is written.
  - Nothing about a saved Result Selection changes: the same figures, the same file, and the same behaviour everywhere else in the window.

## Internal Notes

- **dataset**: Figures saved while a hand-entered triangle is shown a year at a time now land in the monthly cells underneath, as ResQ does.
  - Each figure entered on a coarser view is the row's total at that column's date, so it is written into the one underlying cell for that date and the rest of the triangle is cleared to zero, exactly as ResQ rebuilds a triangle written this way.
  - A view that is coarser on the rows is still refused, because a group of rows has no single date to write to, and so is a vector shown at a longer period.
  - The dataset keeps the period its figures are kept at; only the figures change.
  - The screen still refuses to type or paste on a coarser view; that arrives with the next step of the work.
- **dataset**: A hand-entered dataset that is still empty can now be told to keep its figures at a finer period than the one it is shown at.
  - The save of a dataset whose file holds nothing accepts the period its data should be kept at, so a triangle displayed a year at a time can hold monthly figures underneath, the way ResQ's own editing dialog allows.
  - The period asked for has to divide the one on screen, and once the dataset holds figures it can no longer be moved; both refusals name the reason.
  - A vector has no such setting, as in ResQ, and ignores it.
  - The screen control that offers this arrives with the next step of the work; nothing changes for anyone yet.
- **dataset**: Every dataset record now stores the period the data is really held at, separately from the period it is displayed at.
  - The existing origin, development and period lengths are now the display shape, and a new stored pair beside them is the granularity of the dataset's own CSV, following ResQ's naming.
  - Every writer emits the pair its format takes, the reserving-class index projects it, and a record whose display shape is not a whole multiple of its stored shape is refused.
  - Every part of the app that opens a dataset's data file now reads the stored shape to learn how fine it is, so a coarser view on screen can no longer be mistaken for the data itself; the parts that ask for a dataset to be rebuilt, or that only report what a page is showing, keep reading the displayed shape.
  - Every dataset record already on the server has been given the stored pair by a one-time script, so no reader has to cope with a record that leaves it out.
  - A project now records how fine its source data is when its field mapping is saved, and a project mapped before that is measured once on first use, so a dataset the app builds from the source table records the shape it can be rebuilt at rather than the period it was last shown at.
  - Saving a hand-entered dataset can no longer lose its detail: the length you are viewing it at is saved as a display setting, the figures themselves stay in the file they were entered into, and a save that tries to write values at a coarser length is refused. A dataset that is still empty is simply relabelled to the new length instead.
  - The Dataset Viewer now shows the period a dataset's figures are really stored at beside each length control, offers only the lengths a coarser view can honestly be built at, reopens at the length you last saved, and makes a coarser view read-only so a rolled-up figure can never be typed over.
