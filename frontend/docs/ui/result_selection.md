# Frontend: Result Selection

## Purpose
<!-- MANUAL:BEGIN -->
Result Selection is a Project Instance method window for vector output datasets. It combines selected vector sources, and triangle sources through their latest diagonal values, into a row-level weighted selected ultimate vector.
<!-- MANUAL:END -->

## Entry Points
<!-- MANUAL:BEGIN -->
- [`ui/method_pages/result_selection/result_selection.html`](../../ui/method_pages/result_selection/result_selection.html) - Result Selection iframe page with Details, Method, Chart, Results, Validation, Notes, and Audit Log tabs.
- [`ui/method_pages/result_selection/result_selection_main.js`](../../ui/method_pages/result_selection/result_selection_main.js) - Result Selection state, dataset loading, grid calculation, persistence, and dirty-state wiring.
- [`ui/method_pages/result_selection/result_selection_chart.js`](../../ui/method_pages/result_selection/result_selection_chart.js) - Result Selection dataset-vector chart rendering and per-series visibility controls.
<!-- MANUAL:END -->

## External Interfaces
<!-- MANUAL:BEGIN -->
- Opens from a Project Instance floating window. Home no longer offers a Result Selection launch card, but the shell keeps `openResultSelectionTab` for the standalone restorable tab used by tab restore and UI automation.
- Project Instance creates a new Result Selection from `Add > Result Selection` on a vector dataset row whose Method Type is `None`; existing vector rows with Method Type `Result Selection` open this page for editing directly on the Method tab.
- The page posts generic nested-window dirty state through `arcrho:dataset-dirty`, consumes `arcrho:dataset-save`, and exposes `window.__arcrho_request_close` so Project Instance can ask before closing dirty windows; dirty close requests use the shared page-local confirm dialog and are then confirmed with `arcrho:dataset-close-confirmed`.
- Save delegates to `/result-selection/save`, which validates one complete v2 method payload, server-recalculates the selected output from saved values/weights/overrides, stages `methods/RS@<Name>.json` with the native and coarser output vector CSVs, then publishes the output sidecar after those artifacts are available. The sidecar uses `source_kind: "result_selection"`, `method_type: "Result Selection"`, `status: 0`, and `data_format: "Vector"`; successful save asks Project Instance to refresh its cached table. Saves include the revision returned by load, so an already-open stale page cannot overwrite an automatic dependency refresh.
- Result Selection lives under `ui/method_pages/result_selection/` and uses `ui/shared/tabbed_page/` for reusable tab chrome, `ui/shared/tabs/details/`, `ui/shared/tabs/notes/`, and `ui/shared/tabs/audit_log/` for shared tab presentation, and `ui/shared/components/workspace/workspace.css` for the shared page surface. Its independent Method/Results grids load `ui/shared/styles/scrollbars.css` and `ui/shared/components/spreadsheet/spreadsheet_table.css` directly rather than loading the DSV/DFM Data tab. Result Selection modules still own method persistence, calculations, dirty state, save/close coordination, and RS-specific behavior; the established Result Selection tab IDs and `arcrho:*` contracts remain unchanged, and Result Selection does not load presentation assets from the Dataset Viewer feature directory.
- `Ctrl+PageUp` and `Ctrl+PageDown` cycle through Result Selection tabs with wraparound through the shared tabbed-page runtime, including when the shell or Project Instance host still owns keyboard focus.
- Result Selection imports its dataset-name picker from `ui/shared/components/pickers/` and dataset-type/origin-label utilities from `ui/shared/dataset/`, so those reusable capabilities remain independent of the Dataset Viewer feature.
- Open-window change alert: after a successful method load or save, the page watches its `RS@<name>.json` and output sidecar through `/object_change/fingerprint` (`ui/shared/services/object_change_watch.js`) and shows a one-time "close and reopen" message box when another user or the Engine dependent-propagation job rewrites the method; saves pause and rebase the watch so the window's own writes never alert. The alert offers a Refresh Now action that reloads the window in place when it has no unsaved changes. The alert names the writer: the window reads the object's recorded attribution once after the fingerprint moved and says who saved it, or which automation task rewrote it and the account it ran as. A stale mapped-drive read of the window's own save never raises it: a change is only reported when the object's recorded write is newer than what this window already has. Dependent-propagation jobs started by this app instance never raise the alert: Project Instance broadcasts `arcrho:dependent-propagation-started`/`-finished` scope messages that pause the watch for the job's project and reserving class and rebase it at the terminal status.
<!-- MANUAL:END -->

## Behavior
<!-- MANUAL:BEGIN -->
- Details is three sections: identity - Name, Output Type - then the one Ratio Basis stacked dataset picker holding up to three datasets, followed by the Precedents and Dependents rows, then an Origin Length selector at the shared short field width. One light rule separates each from the one before it, and the sections carry no headings. Its contents take their label and field look from the shared Details primitive `details_form_layout.css`, which the page stylesheet must not restate; see the Frontend Behavior Contract. Output Type and Ratio Basis use the shared dataset-name picker. Each selected Ratio Basis dataset occupies one 30px row with an inline SVG close control that appears when its row is hovered or keyboard-focused, followed by a separate `+ Add datasets` row while fewer than three datasets are selected; the add row has no hover tooltip and disappears at the three-dataset limit. Clicking a dataset opens it, clicking its close control removes it, and dragging a dataset outside the picker also removes it. The Method-tab active Ratio Basis selector stays synchronized with the same list and remains the calculation selector. The Origin Length selector starts from `12`, `6`, `3`, and `1`, then filters out values that are more detailed than any included non-engine source dataset can support; for example, an annual input source allows only `12`, while quarterly-or-finer non-engine sources allow `12`, `6`, and `3`. Engine-generated sources (`source_kind: "engine"`) do not impose this floor because the editor can request a matching length-scoped cache from the data engine.
- Method is the main working tab. It displays one source-value column and one editable Weight column for each selected source dataset. Source columns are ordered into Triangle and Vector groups, followed by the Selected Ultimate and calculated-statistics columns, with narrow blank separator columns between adjacent groups and a single connected header row. `Show Weights As` hides or shows Weight columns without changing the stored weights or calculation. A Weight display dropdown next to `Show Weights As` switches visible Weight cells between editable Index weights and read-only effective row percentage weights.
- The frameless Method toolbar uses the Bornhuetter Ferguson Method-tab layout and groups controls into compact, content-sized Formatting, Statistics, and active Ratio Basis sections. Formatting contains Show Weights As and its weight-display dropdown. Statistics contains Show Ratios as Percentages and the Decimal stepper. The Ratio Basis selector switches among the datasets defined on Details and immediately changes the basis vector used for ratio statistic calculations. Comparing an ArcRho Result Selection with its ResQ counterpart is done by the Sync Reserving Class with ResQ macro rather than from this page.
- Chart appears immediately after Method and plots every loaded source dataset vector plus an explicitly labeled `Selected Ultimate` line for the calculated or overridden selected output vector against the current origin-period labels. Origin, Weight, Reserve, and ratio-statistic columns are excluded because they are not dataset vectors. The shared chart-legend component also used by Dataset Viewer provides the right-side Columns panel and its persistent visibility checkboxes; hiding or showing a series immediately rescales the chart, but clicking the sole visible item leaves it visible. Right-clicking anywhere on a legend item hides every other line, and right-clicking that sole visible item again restores all lines. These display choices remain view-only and do not change method dirty state or saved JSON. The legend moves below the plot in narrow windows, and hovering a plotted point shows its dataset, origin period, and formatted value.
- Inactive Result Selection tabs use the same pale hover fill as Bornhuetter Ferguson tabs, while active-tab fill and weight remain unchanged.
- Method Weight edits synchronize source-cell calculation selection: entering `0` clears the paired source-value cell selection, and entering a positive weight selects it. Double-clicking a selected source-value cell clears its paired Weight to `0`; double-clicking an unselected source-value cell sets its paired Weight to `1`. Weight cells use grid-cell selection rather than a text-caret cursor; double-clicking a Weight cell toggles `0` to `1` and any non-zero weight to `0`. Editable Weight cells display one decimal place, with non-zero values blue and zero values muted gray. Highlighted source-value cells or Weight cell ranges accept typed numeric values, applying the typed value to the paired Weight cells. Pasting a tab/newline range into a Weight cell applies values across visible Weight columns and rows with the same selection sync.
- Method row labels use the same ArcRho origin-header lookup as the Dataset Data tab, keyed by the Details tab Origin Length; the grid uses DFM Ratios-style table font, fixed row, and cell sizing. Statistic columns other than Selected Ultimate use the normal unfilled table background.
- When opening an existing Result Selection method, valid stored `method_tab.origin_labels` from the method JSON take precedence over valid sidecar or ArcRho project-header labels so migrated methods render their saved accident-year labels on first open. Labels must match the selected Origin Length and form one consecutive date sequence. If project headers cannot be resolved, the grid leaves origin labels blank, reports the Origin Start Date error, and blocks saving instead of generating labels from a hard-coded year.
- Method row count follows the loaded origin labels for the selected Origin Length, so longer source vectors do not expand the Method grid beyond the selected annual, half-year, quarterly, or monthly header set.
- Method grid columns can be resized by dragging the right edge of each header; only the dragged column changes width while the total table width follows the column sum. Weight columns stay narrower than source-value columns but keep a minimum width that preserves the `Weight` header label, and column labels wrap to at most three lines before truncating. Source dataset headers use a right-click menu with `View/Edit`, `Add`, and `Delete` actions instead of inline delete buttons.
- The Method and Results grids use the shared spreadsheet table styling and selection controller also used by Dataset and Bornhuetter Ferguson. A click selects one cell, drag selects a rectangle, Shift-click extends from the original anchor, and row or column labels select the full row or column including Total; selected cells expose `aria-selected` and the anchor uses the shared dashed outline. Plain Arrow keys collapse a multi-cell range to one cell moved from its anchor, Shift+Arrow extends the range, Ctrl/Cmd+Arrow moves to an edge, and navigation keeps the active cell visible below the sticky header. `Esc` clears the highlight, while right-click preserves an existing range when invoked inside it and selects an unhighlighted target first. Method source-value cells retain their RS-specific double-click shortcut, which toggles the paired Weight between `0` and `1`; typed numbers and paste still target eligible Weight cells before Selected Ultimate overrides, Total and derived cells remain read-only, and Delete/Backspace sets eligible weights to `0` or reverts selected custom ultimate overrides. Copy produces tab-delimited visible values, scalar paste fills the eligible selection, and matrix paste maps from its top-left cell. Highlighted selected source cells use stronger green, highlighted Weight cells use cyan, Selected Ultimate cells keep their yellow fill, custom Selected Ultimate overrides use red text, and other highlighted cells use blue.
- Default sources are DFM output vectors from the same project, reserving-class path, and Category as the output vector. DFM input triangles and intermediate triangle records are not added by default.
- Users can manually add vector or triangle datasets from the same reserving-class path through the shared dataset-name picker. Added source datasets must have the same Category as the Result Selection output vector; changing the Output Type to another Category removes mismatched loaded source columns. Added source columns are inserted in alphabetic dataset-name order instead of always going to the far right. Vector sources use their first CSV column; triangle sources use each row's latest available numeric diagonal value. Empty source cells display as muted gray `0` values in the Method grid while remaining unavailable for source selection and calculations. The cached dataset index retains each source's native origin length. Only when an engine-generated source's indexed native length differs from the Result Selection Origin Length does the editor materialize a matching length-scoped cache; it reads that exact CSV without changing the source sidecar or native cache. If old index metadata has no native length, the editor first attempts the existing cached CSV and materializes only when that exact load is unavailable or incompatible.
- When a source Dataset, DFM, or Result Selection window in the same Project Instance has unsaved edits, Result Selection can consume its `arcrho:dependency-source-preview` values in-memory without marking the dependent method dirty or writing disk JSON. Active previews are tracked per source window. When a source saves, cancels, or closes without saving, Result Selection removes only that preview, keeps Save blocked until its own method/sidecar snapshot has been restored, reloads any locally added unsaved source or Ratio Basis directly when it is not yet registered in the saved RS, then reapplies other active previews. A preview-clear notification and its durable propagation report are coalesced into one own-method/sidecar reload. A local-only source is reloaded directly by name without rebuilding the dataset index, and a failed local restore remains queued and blocks Save until a newer dependency event retries it successfully. Durable propagation reports are filtered by project, reserving class, and affected RS name, so unrelated saves do not make every open RS window reread its files; initial load, dependency restoration, and save share response leases so an older response cannot replace a newer revision. Save rechecks dependency stability after asynchronous preparation and defers queued refreshes until the write completes.
- The Method tab keeps its toolbar fixed at the top of the tab panel and scrolls the grid body horizontally and vertically inside the grid frame. Method and Results table scrollbars use the same quiet framed tray, compact arrow buttons, and scroll-aware thumb emphasis as the Dataset Data tab.
- `Selected Ultimate` is calculated per row as `sum(source_value * weight) / sum(weight)` over numeric source values with positive weights. If no positive weighted source values exist for a row, the selected ultimate is blank. A custom Selected Ultimate value overrides the calculated value for that row until reverted, and saved output uses the displayed custom-or-calculated value. When the Method grid includes at least one triangle source, it also shows a `Reserve` statistic column after Selected Ultimate; Reserve is `Selected Ultimate - latest developed`, where latest developed is the first triangle source's displayed latest-diagonal value for the row.
- When an active Ratio Basis is selected, the statistic section includes an `Ultimate / Basis` ratio column. The column is labeled `Frequency` when the Result Selection output Category contains `count` and the active Ratio Basis dataset name contains `exposure`. The ratio is `Selected Ultimate / active Ratio Basis` and respects the percentage and decimal settings. Every configured Ratio Basis vector, including inactive bases, is stored in the v2 method JSON, so switching the active basis after load is an in-memory operation. A newly selected or origin-length-adjusted basis must load at the active Result Selection Origin Length; length-scoped caches are used when available, engine-generated basis datasets are provenance-checked/materialized at that length, and mismatched basis lengths are rejected instead of rendering a partial statistic column. Ratio-basis responses carry the current selection/load lease, so a slower response for an older selection cannot replace the newest selection.
- The Results tab shows origin labels, loaded triangle latest-diagonal columns, Selected Ultimate, Reserve when available, and the active ratio statistic column when an active Ratio Basis is selected. Results cells use the shared Method-grid selection and keyboard-copy behavior but remain read-only.
- Saving Result Selection stores each Method source's metadata, native origin length, row values, weights, and source kind in the method JSON; stores all configured Ratio Basis names and row vectors there as well; and stores Method origin labels in the output sidecar. The sidecar `Precedents` is the deterministic union of Method sources and every configured Ratio Basis, while each precedent sidecar registers the Result Selection output in `Dependents`. Reverse-edge registration is required for save success, self/wider dependency cycles are rejected before mutation, and method/sidecar precedent mismatches block loading. Every Save, including a no-op Save, acknowledges that Result Selection by setting its own status to Current and refreshes all downstream data. A review-needed Save revalidates and refreshes exactly the revised Method source and Ratio Basis list, so deleting a stale dependency can recover the method. Missing or unreadable datasets still block Save, but readable precedents that have not been reviewed do not: the save commits and a page-local message box reports their count. After automatic refresh, downstream method-backed outputs remain Review Needed until each method is explicitly saved, while plain input or formula-calculated vectors remain Current and do not show review alerts. A refresh alone does not clear an existing alert. Calculation, propagation, and index warnings remain separate from status. Quarterly and half-year outputs also save coarser aggregate CSVs grouped by half-year/year; obsolete finer-period files are never accepted after the native Origin Length becomes coarser.
- The post-save review warning lists every unreviewed precedent by name. Each name is a keyboard-focusable link that opens its related method window when the dataset is method-backed, or its Dataset Viewer otherwise, while keeping the saved Result Selection unchanged.
- A Result Selection save runs behind the shared saving animation described in [`dataset.md`](dataset.md), titled `Saving Result Selection`, so the page cannot be edited while the save settles. `saveResultSelection` wraps the save in it, so it covers every save entry point: the Save bar and the shell `arcrho:dataset-save` and `arcrho:result-selection-save` messages. The animation instance is created in `result_selection_main.js` and passed to the model through `ctx.rsSaveProgress`, so an install without a document (tests, embedded hosts) runs the same save with an inert stand-in. The card streams the dependent walk's live updates before the spinner is dismissed, which still happens before the post-save review warning and before the Engine-unavailable message box so no dialog opens behind it. No save closes the window: both entry points (Save bar and shell save messages) show the saved-dependents notice after a clean walk (`propagationClean`) and leave the method open.
- Cancel closes the Result Selection window; when dirty, it first shows the shared page-local confirmation before discarding changes. The modal remains inside the Result Selection page, traps focus, and makes the page behind it inert.
- The Validation tab is intentionally reserved as a placeholder.
- Notes reuses the presentation and editor interactions under `ui/shared/tabs/notes/` for formatting, path highlighting, indentation, and dirty-state callbacks. Result Selection saves notes only in the output dataset sidecar; method JSON contains no notes section.
- Audit Log loads the saved output dataset sidecar's canonical `audit_log` on tab activation and after save, then renders it newest first with the shared Dataset/BF/RS/DFM audit table and loading/error/empty states. Viewing or refreshing this history does not change Result Selection dirty state or add audit rows to the method JSON.
- Right-clicking a Result Selection page tab temporarily moves that live tab page into a draggable, resizable floating window inside the Result Selection page, using the same shared tab pop-out behavior as DFM and Dataset. The floated tab keeps its original controls, event handlers, dirty-state behavior, grid state, and notes state because the actual tab DOM is moved rather than cloned. Closing the floating window, right-clicking its titlebar, or right-clicking the grey popped tab button docks the tab back into the normal tab area.

## Data/State/Caches
<!-- MANUAL:BEGIN -->
- Opening a valid current Result Selection calls `/result-selection/load` once. The app server reads only `methods/RS@<Name>.json` and the output's own sidecar in bounded parallel; the frontend renders persisted sources, weights, labels, selected/calculated values, overrides, and Ratio Basis statistics without loading the dataset index, source sidecars/CSVs, basis sidecars/CSVs, or calculated dependencies. New methods, source/basis picker actions, and explicit Origin Length changes still load the dataset catalog and use `/dataset/cache/load`; source reloads use at most four concurrent workers with deterministic order and stale-response guards.
- The current method marker is `arcrho-result-selection-method-by-tab-v2`. Keys use underscores, including `details_tab`, `method_tab`, `loaded_datasets`, `ratio_basis_datasets`, `active_ratio_basis_dataset`, `ratio_basis_values`, `calculated_ultimate`, `selected_ultimate`, and `method_metadata`. Notes remain excluded and live in the output sidecar. `details_tab.ratio_basis_datasets` stores up to three case-insensitively deduplicated names; `method_tab.ratio_basis_values` stores the same configured order as `{name, values}` records, each with exactly one finite-number-or-`null` value per origin row. `loaded_datasets[*]` stores source metadata, native `origin_length`, values, and nonnegative weights with the same row count. `calculated_ultimate`, `ultimate_overrides`, and `selected_ultimate` are also row-aligned. Persisted numeric arrays use symmetric half-away-from-zero rounding to six decimal places. No separate `selected` array or `value_source` field is stored.
- An exact v1 method is upgraded once during load: configured dependency sidecars/caches are read with bounded parallelism, every source and Ratio Basis vector is refreshed, selected values/output files are recalculated, and missing Ratio Basis reverse edges are repaired before v2 is returned. Unknown formats, orphan method/sidecar pairs, identity/origin mismatches, and failed upgrades are blocking load errors; the page cannot overwrite them with a blank method. A current v2 load never takes this dependency-read path.
- Project Instance's cached dataset index recognizes saved Result Selection method JSON files and reports their output vector rows with Method Type `Result Selection`.
- When a new Result Selection or a later picker action needs inventory inside Project Instance, it can reuse the parent page's already-loaded dataset-index snapshot. Existing v2 opening needs no source inventory. Explicit picker refreshes and post-save Project Instance refreshes still request the authoritative server index.
