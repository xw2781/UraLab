# Frontend: Dfm

## Purpose
<!-- MANUAL:BEGIN -->
DFM feature across Details, Data, Ratios, Curves, Results, Notes, Links, and Audit Log on top of dataset context, with method metadata in Details. Links follows Notes.
DFM Notes reuses `ui/shared/tabs/notes/` for path highlighting, `Tab`/`Shift+Tab` indentation, `Esc` to exit editing, spellcheck off, and whole-note display formatting while preserving DFM's `dfm_persistence.js` save flow. File paths render as deep-blue underlined non-bold text, known file extensions stop the token before trailing prose, and right-click shows `Open File`, `Copy File Path`, plus `Open as Read-Only` for Excel workbooks; focused editing shows plain text until focus leaves the textarea and toolbar. DFM relays nested `arcrho:open-path` requests to its parent so Notes links keep working in popped-out tab surfaces.
High Contrast keeps Light colors, black spreadsheet text, and red excluded ratios.
<!-- MANUAL:END -->

## External Interfaces
<!-- MANUAL:BEGIN -->
- Exchanges `arcrho:*` messages with shell and workflow iframe.
- Reuses dataset APIs and reserving class selectors.
- DFM lives under `ui/method_pages/dfm/` and uses `ui/shared/tabbed_page/` for reusable tab chrome plus the matching `ui/shared/tabs/data/`, `ui/shared/tabs/details/`, `ui/shared/tabs/notes/`, `ui/shared/tabs/links/`, and `ui/shared/tabs/audit_log/` modules for shared tab presentation/runtime. DFM modules still own method persistence, dirty state, save/close coordination, calculations, and page-specific behavior; `dfm_data_tab_adapter.js` connects those feature concerns to the host-neutral Data tab without importing Dataset Viewer assets. Established DFM tab IDs and `arcrho:*` contracts remain unchanged.
- DFM Data grid uses the shared Data-tab `#tableWrap` scroll frame, while the table draws its own complete cell-grid perimeter inside that frame. The Data and Ratios scroll frames use the same shared neutral border color, and the separate table edge matches the Ratios-tab structure without changing sticky-header or sticky-row-label behavior.
- The shared Data tab keeps native scrolling inside `#tableWrap` without idle row/column snapping, so mouse wheel and trackpad scrolling can stop with partial cells visible.
- DFM Ratios tab now uses a dedicated framed scroll host (`#ratioWrapHost` -> `#ratioWrap`) so sticky headers/first-column overlays are contained within the ratio grid viewport instead of page-level scrolling.
- The Ratios tab's last column, `<age> - Ult`, is each average row's own tail factor rather than an average: a User Entry or frozen benchmark row shows and keeps the value entered there (ResQ's `CustomAverages(i).TailFactor`), a computed average row stays at 1, and the row selected in that column supplies the Initial Selection tail on the Curves tab. No formula runs in that column.
- DFM Curves tab (`dfm_curves_tab.js`, the ArcRho counterpart of ResQ's Curves | Data tab) sits between Ratios and Results. Its grid shows the Initial Selection (the Ratios tab's selected factor per period and its tail), an Include column, the Exponential Decay, Inverse Power, Power and Weibull curves fitted by log regression to the included factors, any user value columns, and then the Selected Estimate Number, Selected Value, Cumulative Value, Cumulative Percentage and Incremental Percentage. Below the periods come the tail row (`<age> - Ult`), the Fit / A / B / C / R-squared % rows, and the Tail Pattern block, opened by a quiet rule and headed by the Tail Pattern row whose X marks the column the tail runs off along, followed by one row per Future Dev. Period. That column carries the same green fill through every future period row, so the choice and the run-off it produces read as one block, and clicking a future period cell picks its column exactly as clicking the X row does; the X and the fill name the column the figures were built from (`selected_tail_pattern_column`) rather than the stored setting, so a setting pointing at a removed column shows the column actually used. The toolbar holds Fitting Method (Log Regression; a method imported from ResQ with Least Squares keeps that setting, shows a notice, and is still fitted by log regression), a disabled Weighting selector, the Future Dev. Periods stepper, and Free Fit C. The Curves and Results toolbars are the same control bar: both carry `dfmPageControls`, which owns the bar, its labels and its stepper fields once, so a control added to either sits in the same box. Every scrolling area of the DFM page carries `dfmScrollArea`, which owns the 20px tray, the quiet thumb and the single step arrow per tray end, so the Curves grid scrolls like Details, Ratios and Results; the Curves grid frame closes on its left and top edges and takes the same focus ring as the Results frame. Clicking a value cell selects that column for the period (or for the tail, or as the tail pattern on the X row); clicking a column header selects it for every period and the tail; clicking an Include cell toggles it; double-clicking a User Entry cell edits it; right-click offers Copy Value, Add User Column, and Rename / Remove User Column. The grid paints ResQ's own cell colours: a chosen cell takes the pale green the Ratios tab fills a selected average with (`--ar-spreadsheet-weighted-selection-fill`), a User Entry column is pale cyan, the Selected Value carries the same pale yellow Result Selection fills its Selected Ultimate column with, and the Selected Estimate Number beside it carries no fill. Setting Include to No strikes both the flag and the Initial Selection factor it drops, in the Ratios tab's `--dfm-excluded-ratio-color`, which that tab's strike now reads from the same place; a struck factor keeps reading as struck when it is also the chosen one. Spacer cells carry no fill but keep their grid edges, and a spacer row's label cell is a row header like any other, so neither the rules nor the frozen label column breaks where the grid has nothing to say. Each curve's tail factor is the product of its fitted values over the Future Dev. Periods; the selected values are the factors the Results tab's ultimates and the percentage developed use, so a default tab (Initial Selection everywhere) leaves the method exactly as the Ratios tab selects it. The calculation is owned by `arcrho_api/dfm_curves.py` and mirrored in `dfm_curve_fit.js`; the Graph and Monthly Pattern sub-tabs of ResQ are not reproduced, and Curves-tab edits are outside the Ratios-tab undo history.
- DFM Data tab wraps `#tableWrap` inside `#tableWrapHost`, so shared data-surface sticky header/first-column behavior remains pinned inside the table viewport during Data-tab scrolling.
- For an existing method URL, DFM page boot puts the shared Data tab into persisted-method mode: it skips project/dataset discovery, sidecar synchronization, index/conflict checks, and ArcRhoTri startup, then hydrates Data directly from the v2 method snapshot before Ratios and Results render. New methods retain the explicit source-selection/refresh flow.
- Opening a DFM tab now lands directly on the Details page instead of showing a startup chooser. The Details `Name` field has a `...` selector that reads the selected Reserving Class folder's cached `index.json` through the DFM method-index endpoint and lists DFM-backed dataset names associated with that path. Selecting a name commits the normal Details lookup, so the existing local DFM JSON load flow applies the method settings.
- DFM Data and Results table cells that display percent-formatted input values always use one decimal place (`0.0%`), independent of the DFM ratio decimal-place controls.
- DFM Results tab table now shows per-origin columns in this order: `Latest <Input Triangle Name>` (latest observed value from DFM Data-tab triangle row), `Reserve` (`Ultimate - Latest`), and `Ultimate`; Results header cells allow wrapped text so long input triangle names are readable instead of truncating to one line.
- DFM Details `Output Type` is the vector dataset type that the DFM method attaches to and is selected from the current project's `dataset_types` Vector rows. `Input Triangle` is selected from the same project dataset-type picker filtered to `Triangle` rows. DFM Data refresh loads an exact input cache when present; generated input triangles can request ArcRhoTri to create a missing shape when the base sidecar exists. Manual/imported input triangles stay local-cache-only: DFM can derive coarser period requests from finer cumulative local caches, such as quarterly to annual, and rejects requests for finer detail than the local cache provides. DFM shows an explicit alert/status error when the input triangle sidecar is missing or a manual/imported requested period detail cannot be derived.
- DFM Ratios restores the machine-local user's last Select/Edit mode when the page opens; if no saved preference exists or local storage is unavailable, it opens in `Edit` mode. Changing mode from the context menu or with `S`, `E`, or `Ctrl+E` updates that local preference without changing method dirty state or saved method JSON. Select mode creates a temporary cell/range highlight for copying without changing ratio exclusions, active columns, selected average formulas, or average-row order; table headers retain the normal arrow cursor. Highlighting alone does not change User Entry values, but typing a digit or decimal point starts direct entry in the active highlighted User Entry cell in either Select or Edit mode. The main and average-table Ratios context menus show the dynamic `Switch to Edit Mode` / `Switch to Select Mode` command with its pen/hand icon after the text; the main menu follows it with `Show Data` / `Hide Data`, and there is no separate Ratios toolbar. In Ratios terminology, **selected** cells are persisted method choices shown with a light-green fill, while **highlighted** cells are the temporary copy/focus range shown with a continuous dark-green outer border. Clicking a Ratios table cell or header focuses the table surface; while it remains focused, `S` enables Select mode and `E` enables Edit mode. `Ctrl+E` toggles between Select and Edit whenever the Ratios tab is active; the shell and Project Instance forward this command to the active DFM, and the DFM captures it across its whole page, including while a control has focus. Plain `S` and `E` remain disabled while typing in controls. In Select mode, an Arrow key collapses the highlighted range to a new single cell one step from its anchor, Shift+Arrow extends the range from that anchor, Ctrl/Cmd+Arrow collapses it to the corresponding table-edge cell, and Ctrl/Cmd+Shift+Arrow extends it to that edge; keyboard movement keeps the active cell visible and works in the main Ratios, average-formula, and selected-summary tables. Pressing `Enter` in a highlighted main-ratio range toggles each valid cell's exclusion status as one undo step. Pressing `Enter` in a highlighted average-formula range selects the highlighted formula for each covered development column and applies the green selected fill; if one column's highlight spans multiple formula rows, the topmost highlighted row wins. Enter does not apply these range actions in Edit mode. The view-only Show Data command interleaves the current Data-tab observed values before their corresponding ratio columns; average-formula and selected/cumulative rows receive blank data-column spacers so all logical ratio columns remain aligned. Toggling Show Data does not change ratio indices, formulas, saved method JSON, or dirty state. Highlighted cells and rectangular ranges use the continuous dark-green outer border across the main Ratios triangle, average-formula table, and selected/cumulative table; covered development-column headers and row labels use the shared darker-gray, regular-weight selected-label style. Edit-mode summary-cell actions do not apply that temporary label emphasis. Starting a highlight in another Ratios table automatically clears the previous table's highlight and label emphasis, while `Escape` clears the active highlight. `Edit` clears any temporary highlight before restoring table mutations and uses the Windows-style Handwriting pen cursor over table cells. The Ratios, Ratios summary/selected rows, and Results tables support highlighted-cell copying consistent with Dataset grids: a single rectangle copies as tab-separated text, and multiple separate ranges copy the top-left highlighted cell. The shared table context menu keeps only `Copy value` and `Export data`; the main Ratios menu places its mode and data-view commands before `Copy value`, while the average-formula and percent-developed context menus retain their table-specific commands. Shift/Ctrl-drag highlights Ratios cells in Edit mode without replacing the existing strike-toggle drag gesture. Existing selected-ratio/selected-formula fills are preserved.
- The average-formula summary table context menu also begins with the dynamic Select/Edit mode switch and updates the same machine-local mode preference as the main Ratios menu.
- DFM Ratios User Entry formulas highlight referenced average-formula cells by exact quoted average-formula name. While a formula is being edited, that one cell's highlights come from the formula bar's draft rather than from the saved formula, so retyping or dragging a reference onto another row clears the fill from the row it left instead of leaving both rows filled until the commit; abandoning the edit returns the fill to the saved formula. They may also read an existing dataset instance from the current Reserving Class with `[Dataset][row]` for a Vector or `[Dataset][row, col]` for a Triangle. Every dataset named by an authoritative saved formula is a DFM precedent: the DFM output sidecar lists it under `Precedents`, the source sidecar lists the DFM output under `Dependents`, and saving that source makes the DFM output Review Needed through the normal dependency walk. `display inputs` never create graph edges. Row and column positions are one-based; axis labels may be used instead, and a numeric label can be quoted when it would otherwise be a valid position. Typing `[` in the formula bar opens a keyboard-accessible dataset list; subsequent text filters names by a case-insensitive contains match, and choosing a name inserts `[Dataset][` ready for coordinates. Negative positions count backward from the dataset's valuation-valid boundary: a Vector's boundary is the last origin period on or before the project's Development End Date, or the last non-empty row when the data stops earlier, so `[-1]` is the valuation period whether or not the rows after it hold values; a Triangle trims trailing empty calendar diagonals. Nulls inside that valid range are not skipped, so a negative position may still identify a blank cell and produce the normal blank-cell validation error. While the formula bar is in edit mode, the active referenced average-formula cell in the same development column gets a thicker outline in that reference's own colour; dragging that outline to another average-formula row rewrites the row reference in the formula bar immediately. The drag starts from the cell's border, as a spreadsheet moves a range: within a few pixels of that border the pointer becomes the move cursor, and it stays the move cursor for the whole gesture. Because the formula bar is editable in Select mode as well, and Select mode paints every cell's cursor with `!important`, the move cursor is declared `!important` too; without that it appeared only in Edit mode. The rest of the cell keeps the click cursor it shares with every other candidate cell, because clicking there picks that reference rather than dragging one. The formula bar floats over the grid instead of occupying a frame above the average-formula summary table: it is anchored just above the cell it edits and drops just below it only when there is no room above. Its width follows the content it shows, under two ordered rules: the bar never extends past the visible ratio frame, and within what remains it grows as wide as the row label and formula text need. It slides left rather than letting its right edge run past the frame, and re-applies both rules as the formula is typed and whenever the app window or DFM frame is resized. The bar carries no action buttons: it is the `fx` badge, the row label, and the formula. The `fx` badge carries no tooltip because it is the bar's drag handle: dragging it lifts the bar out of the ratio grid's scroll frame and leaves it wherever it is dropped inside the visible DFM page, still sized to what it shows and still drawn under its own validation tooltip and dataset list. A press that does not move the pointer changes nothing. That hand-placed position is temporary and belongs to one target: showing the bar for any other cell or linked dynamic array, returning to this one afterwards, or hiding the bar all restore the anchored position above the cell it edits. There is no pick-from-Excel control either, so an external reference is entered by typing or pasting it into the formula bar. Pressing a User Entry cell toggles that cell's formula bar: the first press shows it, pressing the same cell again hides it, and pressing any other User Entry cell shows the bar for that one. The toggle acts on the capture phase of the press, before either interaction mode selects the cell, so Select and Edit mode behave identically; a target toggled off also survives a Ratios re-render, which Edit mode performs on the same press. A linked dynamic array counts as one target, so any of its cells toggles the same bar. The toggle is ignored while an edit session is open or a commit is pending, and a target left toggled off stays off only until the user moves to a different one.
- DFM Ratios User Entry formula cells accept standard external Excel range references containing the full workbook path, worksheet, and address, such as `='C:\Folder\[Book.xlsx]Sheet 1'!$A$1:$C$2`. The referenced matrix spills from the anchor into adjacent User Entry rows and development columns while every table cell continues to display its stored numeric value. Selecting any affected cell shows the shared range formula in the editable formula bar; editing from any cell updates the range through its anchor. Hovering any cell of the linked dynamic array also moves the formula bar over that array, so the shared formula reads directly above the cells it fills; leaving the array returns the bar to the active cell, and hover never retargets the bar while its input is being edited or a commit is pending. A thin ArcRho-blue outer border with a light inset glow marks the range without changing interior fills, and activating any cell inside it strengthens the glow slightly. When Show Data is enabled, the border and glow continue across the interleaved blank data spacer cells so the logical formula array remains one connected rectangle. Changing, clearing, or overwriting the shared formula restores cells no longer controlled by that range to `1`. Saving a dataset referenced by an authoritative User Entry formula refreshes the dependent DFM server-side through the Engine dependent-propagation walk: the referenced values are re-resolved, the method JSON and outputs are republished, and the output is marked Review Needed. Opening the DFM then shows the refreshed persisted values, stays clean, and clears the Review Needed flag on the next explicit Save. Excel-only links retain their check-only open behavior, which compares saved workbook values once for the applied revision without changing DFM state; manual refresh actions remain mutating and require Save when values change.
- The DFM Links tab appears immediately after Notes and derives its inventory from external Excel references in Ratios User Entry `inputs`, including standalone range formulas and external references embedded in expressions. It uses the reusable shared Links presentation and shared Excel-reference parser also used by Dataset Viewer: an **Excel** pane headed by a green stamp in the colour Excel-linked cells wear in the grid, below the ArcRho pane and separated from it by a draggable divider that starts at the middle of the tab, each pane a scrolling frame with the scrollbar drawn like the Data and Audit Log tabs' (20px with step arrows), holding one single-line row per workbook range with the workbook file name under Source and no kind badge, since the section stamp names the kind, `Sheet!Address` under Reference, the Ratios destination as the block the range fills (`first row~last row / first column~last column`, each side collapsing to one label when the range covers one), and the cell count; the columns resize by dragging a header's right edge and re-fit to the frame when it is resized. The tab retains the latest broken/stale/unverified check warning so unrelated status-bar messages cannot erase it, and titles it `Excel links need attention` while any reference is broken. The tab has no toolbar; right-clicking a workbook row puts `Open workbook`, `Open workbook as Read-Only`, `Copy file path`, and `Open file location` at the top of the context menu, targeting the row that was clicked; the copy puts the workbook's full path on the clipboard and the location shows the file in File Explorer, selected where the desktop host exposes that and otherwise by opening the folder holding it. Right-clicking the table background offers `Refresh all` and `Break all` when no rows are selected. Clicking a row selects it, Ctrl/Cmd-click toggles individual rows, and Shift-click extends a contiguous selection; right-clicking inside the selection preserves it while right-clicking an unselected row selects that row first, and while rows are selected refresh and break act only on that selection. A menu entry is omitted when it has nothing to act on, and the menu does not open while an action is running. Breaking replaces every related User Entry consumer with its current numeric value, including every destination controlled by a spilled range, then follows normal DFM dirty/save behavior. The inventory and freshness warning are runtime views derived from Ratios state and are not separate persisted method sections. The on-open check reads the saved source cells, so a reference the workbook refuses is separated from a value that merely drifted: a broken reference opens the same **Excel Link Reference Error** message box the Dataset window uses — naming each failing source cell, the Ratios User Entry destination it feeds, and the reason — instead of the stale/unverified status line, and the User Entry cell it feeds keeps its saved ratio and renders red (`#ratioWrap td.summaryCell.excelLinkError`) instead of the linked-cell green until the reference is fixed. The record lives on the summary runtime rather than on the cell, so a Ratios re-render paints the same cells red again. A Links-tab refresh clears the marking for every cell it refreshes, re-marks the ones that failed again, and sends every failure to that message box instead of the formula-bar validation error — named references as a list, and cells that failed with no reference to name as a count alongside them. The Project Instance Excel Link Manager can repoint a saved workbook path across the whole reserving class; by default it patches User Entry `inputs`/`display inputs` through the canonical owned-patch flow with Excel-linked values frozen and the publication revision unchanged, so outputs, sidecar status, and dependents are untouched. Its opt-in recalculation checkbox instead refreshes the linked User Entry values with the client Links-tab rules (finite results greater than zero, ranges spilling literals into non-anchor cells) and commits through the normal DFM save, including publication, audit, and dependent propagation. Either way, a dirty open DFM whose method was retargeted hits the normal owned-revision conflict on its next save.
- DFM Ratios User Entry rows accept a single clipboard value or a rectangular Excel cell range pasted from the active User Entry cell. Range pastes are applied atomically across User Entry rows and development columns; invalid, non-positive, non-rectangular, non-User Entry, or out-of-bounds destinations are rejected without partially changing the table.
- DFM Results tab adds a `Ratio Basis` selector above the table (typed input + `...` dataset picker window backed by `ui/shared/components/pickers/dataset_name_picker.js`). The picker exposes all dataset names from current-project `dataset_types` (including calculated and non-triangle/vector types), while Result-column extraction supports Triangle/Vector selections and reports unsupported geometry explicitly. Results also includes a dedicated `Ultimate Ratio Decimals` input (default `2`) used only for the `Ultimate Ratio` percent column formatting. After selection, Results appends `Ratio Basis: <dataset>` and `Ultimate Ratio` columns after `Ultimate`; `Ultimate Ratio = Ultimate / Ratio Basis`. Existing v2 methods render this column entirely from the embedded, exact-origin-aligned Ratio Basis snapshot. Selecting a different basis or explicitly refreshing a review-needed method may read the source and replace that snapshot. Results also appends an unfilled `Total` row that sums numeric columns; `Ultimate Ratio` total is computed as `Total Ultimate / Total Ratio Basis`. Clicking a Results row label selects that row, and clicking a column header selects that column including its Total cell; implicated labels receive the shared spreadsheet selection emphasis.
- DFM method save writes Results vector CSV variants under `projects/<project>/data/<ReservingClassFolder>/datasets/<OutputDataset>@<OriginLength>.csv`, the v2 method under `methods/DFM@<MethodName>.json`, and one canonical output sidecar under `sidecars/<OutputDataset>.json`. The sidecar records `method_name`, `source_kind: "dfm"`, `method_type: "DFM"`, `status`, and the current dependency graph; Input Triangle, Ratio Basis, and datasets referenced by Ratios User Entry formulas are precedents. Save stages the full publication under the reserving-class lock, suppresses unchanged files, replaces the sidecar last, and rolls back on failure. A valid v2 Save uses the embedded Input Triangle and Ratio Basis snapshots instead of reopening precedents to validate duplicate labels. Readable precedents that remain Review Needed do not block Save; after the save commits, a page-local message box reports how many have not been reviewed. Selecting a new source or explicitly refreshing it still requires a readable CSV with compatible period and row/column geometry. Dependent calculated datasets and Result Selection methods refresh only when the published ultimate changes. V2 stores no absolute CSV paths. When source period is Monthly/Quarterly, save also emits the established coarser vector variants in the same reserving-class `datasets/` folder.
- The post-save review warning lists every unreviewed precedent by name. Each name is a keyboard-focusable link that opens its related method window when the dataset is method-backed, or its Dataset Viewer otherwise, while keeping the saved DFM unchanged.
- DFM Audit Log loads the saved output dataset sidecar's canonical `audit_log` on tab activation and after save, then renders it newest first with the shared Dataset/BF/RS/DFM audit table and loading/error/empty states. This read-only view is not added to DFM method JSON or dirty-state snapshots.
- DFM pages include a bottom Save/Cancel row that uses the same DFM method persistence path as shell `File -> Save`. Save writes the current DFM method JSON plus Results CSV outputs; after an existing local method has been loaded, editing Details `Name` and using normal Save renames the DFM identity by writing the new method/cache files and deleting the previous method/cache files only after the new save succeeds. Save As creates a separate method file. Cancel closes the DFM window; when dirty, it uses the shared page-local close confirmation before discarding and restoring the last loaded/saved clean DFM method state. The confirmation states, "Unsaved changes will be discarded and the window will close." Yes discards the changes, while No returns to the unsaved page. Linked-value validation is bounded to 30 seconds so a stalled workbook or dataset request releases the formula bar. Excel address column letters are automatically normalized to uppercase while typing and before persistence. The formula bar is positioned in the ratio-grid scroll host's coordinate space, so it travels with its anchor cells while users scroll, and it re-anchors and re-sizes when the app window or DFM frame is resized — unless the user has dragged it away by its `fx` badge, in which case it keeps the place they put it and only stays inside the visible page so the row label and formula text stay over the cells they belong to and inside the visible frame. The measured text width is reused across scrolls and repositions and re-taken whenever the shown content changes: on a resize, which can also change zoom; while the `Validating…` chip occupies room of its own; and on every swap between the editable input and the rendered display. That last case matters because the display draws each reference as a padded pill and so needs more room than the same formula as plain input text, and leaving edit mode through Escape or a committed Enter must not leave the formula clipped.
- User Entry formulas that reference another average-formula row fill the referenced summary cells in the same development column, and only while the User Entry cell that names them is the one in view: the highlight anchor in Select mode, the active cell in Edit mode, or the cell whose formula is open in the formula bar. No other User Entry row's references are filled at the same time, so the table shows the sources of one formula rather than of every formula at once. Each distinct reference in that formula gets its own fill colour from a six-colour palette, handed out in the order the formula names them and reused from the start if a formula ever names more than six rows; a row named twice keeps the colour it was given first. The colours are recomputed when the highlight or active cell moves, when the mode changes, when User Entry formulas are saved, and when summary values recalculate, so they follow changed formula references and source-cell updates.
- User Entry formula values re-evaluate whenever a referenced average-formula row's value changes, for example after ratio exclusion edits in the Ratios triangle. A formula that mixes row references with dataset or Excel references re-evaluates using each external reference's last-resolved value from the current session without a new precedent or workbook read; until such a value exists, the stored evaluated value is kept. Opening a method whose formulas reference datasets resolves those references once, in the background, purely to warm this session cache — the warm-up never changes values, dirty state, or files. Every User Entry evaluation path (commit, paste, array fill, linked refresh, open-time auto-evaluation, and recalculation) computes referenced average-formula rows with the same canonical engine rather than reading the displayed cell text, then takes each one at the Details tab's Decimal Places, so a reviewer multiplying the digits printed on the Ratios tab reaches the User Entry factor exactly. `averageRowReferenceValue` in `dfm_ratio_calc.js` and `arcrho_api.dfm_contract.average_row_reference_value` are that one rule, and changing Decimal Places therefore re-evaluates every User Entry row and everything downstream of it, not just how the numbers are printed. Dataset, Excel, and array references are not rounded; they enter the formula as stored. The formula language is numbers, `+ - * /`, parentheses, row references, dataset references, Excel references, and one function: `ROUND(x, digits)` (digits optional, default 0), which rounds half up on the decimal text so `ROUND(2.38625, 4)` is 2.3863. The browser evaluator (`evaluateSimpleMathExpression`, backed by `roundHalfUp` in `dfm_ratio_calc.js`) and the server contract (`arcrho_api.dfm_contract.round_half_up`) round the same way, so a formula such as `= ROUND(2.38625, 4) * [Accounting Cutoff][-1]` evaluates to one value wherever it is recalculated. Any other function name is not a formula and is refused. The Apply Growth and Cutoff Adjustments macro writes the plain average row name and no longer wraps it in `ROUND`, because the row already enters at the Ratios tab's Decimal Places; a formula written by an earlier version of the macro still evaluates to the same value.
- The User Entry formula bar accepts Excel-style array constants for horizontal spill entry: `={1,2,3}` or `=TRANSPOSE({1;2;3})`. Spill values beyond the visible summary-table range are ignored, the full array formula is kept only in the first filled cell, following cells store the resulting values, and all filled columns are selected from the same User Entry row. The filled array receives the same blue outer border and light glow as an external Excel range without changing its interior cell fills.
- Right-clicking anywhere in the DFM Ratios selected-summary table opens a selected-summary context menu with `Show Percentage Developed Curve`. The floating `% Developed Curve` window reads the rendered `% Developed` row and places actual data points at the matching Data-tab development-month labels for each ratio column, so a ratio period like `(1) 11-23` plots at month 11. The curve starts at month 1 and `0%`, then interpolates monthly values to the first actual point. Each displayed ratio column owns the segment ending at that column's actual point; the `Curve Type By Segment` section presents those segments in a horizontally scrollable two-row table with `Period` labels and in-cell `Curve Type` dropdowns. Segment curve choices default to linear interpolation and include smooth, step, exponential, logarithmic, and power choices. The window also has an optional Prior Project input with the shared project tree picker; selecting a prior project does not change the active DFM project, and clicking `Add Curve` fetches the same Reserving Class path and DFM method name from that project and overlays its `% Developed` curve. If the matching DFM method cannot be found or cannot produce curve points, the window shows the error and leaves the current graph unchanged. The curve window does not persist display-only chart settings in DFM method JSON.
- The DFM Ratios average formula table right-click menu includes `Plot Table Data`, which opens a draggable and resizable floating plot window. The plot reads the current rendered summary table values, charts each average formula row plus the current `Selected` row across the current development-period columns, and shows a row legend. The plot window toolbar includes zoom, hand-drag, pencil tools, and a graph-mode toggle; `Ratios` plots the rendered summary values, while `% Dev` treats each row as the selected ratio row, computes its right-to-left cumulative product, and plots `1 / cumulative` as percent developed for each column. Zoom mode changes the chart cursor to zoom-in, dragging a chart region zooms into that selected area, a single chart click resets to the original full view, hand-drag mode pans the full chart view with pointer-captured dragging, pencil mode lets users click an average-formula point to make that formula the selected value for the clicked development period, and `Esc` deselects the active tool. Pencil clicks ignore the `Selected` line itself. The plot legend follows the Dataset Viewer chart legend behavior: clicking a legend label row or checkbox hides/shows that line, `Select All` controls all lines, individual toggles keep at least one line visible, and right-clicking a legend row isolates that line or restores all lines when it is already isolated.
- When loading DFM JSON from RPC/local method payloads, DFM reconstructs runtime average formula rows from the `average formulas` object. Supported inferred labels are `Volume - all`, `Volume - <n>`, `Simple - all`, `Simple - <n>`, and the same labels with `Ex hi/lo` or `Ex hi/lo x<n>` suffixes; unresolved labels are skipped.
- DFM template files use `.arc-dfm` extension only (`DFM_Template@<Project>@<ReservingClass>.arc-dfm`); legacy `.arcdfm` suffix is not accepted.
- After required Details inputs are all populated, DFM checks whether the instance JSON exists at the standard local save path; if missing, it does not show the former inline warning/`Confirm` action beside `Name` (new-object guidance is status-bar only).
- On the same local instance-file lookup, once DFM Details has committed values for `Project`, `Reserving Class`, and `Name`, DFM automatically checks for a matching local method JSON. If found, it auto-loads the file and reports the loaded file path in the status bar. If not found, it reports a yellow status-bar warning (via shell status `tone=warn`) with the exact text `This method object has not been created yet, changes will be saved to a new container.` The lookup does not wait for `Input Triangle` / `Output Vector` / period lengths.
- Details `Input Triangle`, `Origin Length`, and `Development Length` are saved properties of the current DFM instance, not local instance lookup keys; changing them marks the current DFM dirty and follows the normal dataset refresh behavior without reloading method JSON from disk. Saving the DFM object writes the adjusted length values back into the stored method JSON.
- DFM Details `Name` is a plain text input with a project/path-scoped selector backed by the Reserving Class folder's `index.json`; it does not use the older browser-local saved-name dropdown or delete action.
- Temporary debug aid: DFM local-method lookup currently emits short status-bar debug messages (for trigger/skip/checking-path) prefixed with `Debug: DFM local method lookup ...` to help verify the frontend lookup flow during Details input changes.
- DFM local-method lookup scheduling is debounced and reason-coalesced; higher-priority `details-change` lookups are not downgraded by later `tab-activated` triggers (avoids false `dirty + tab-activated` skips immediately after Details edits).
- Shell tab activation/state-request messages refresh DFM edit-state reporting only; they do not trigger local method lookup.
- Existence checks run on committed input changes (`change`/selection/blur`) rather than every typing keystroke.
- DFM responds to shell `arcrho:assistant-context-request` messages with the active DFM tab, Details field values, dirty state, standard method JSON path, and current in-memory method payload so ArcBot can analyze the active method even when host-side direct reads from the server share are denied. After an ArcBot JSON edit is applied by the host, DFM receives `arcrho:assistant-json-updated` and schedules a local method reload.
- DFM watches the active local method JSON file for external disk changes. When the page is clean, a changed JSON file is reloaded into the active GUI automatically; changed Ratios exclusion cells and Average Formula selection cells briefly flash blue so API/ArcBot edits are easy to inspect. When the page is dirty, DFM does not overwrite in-memory edits and posts a warning so the user can save or reload deliberately.
- A DFM save runs behind the shared saving animation described in [`dataset.md`](dataset.md), titled `Saving DFM Method`, so the page cannot be edited while the save settles. `saveRatioSelectionPattern` wraps the save in it, so it covers every save entry point: the Save bar, the shell `arcrho:dfm-save` and `arcrho:dfm-save-as` messages, and Excel bridge saves. The card streams the dependent walk's live updates before the spinner is dismissed, which still happens before the post-save review warning and at the start of the save error path so no dialog opens behind it. No save closes the window. The explicit Save command (Save bar button and the shell `arcrho:dfm-save` message, which routes through the same bar handler and its in-flight guard) shows the saved-dependents notice after a clean walk (`propagationClean`) and leaves the method open; Save As and Excel bridge saves show no notice, and a failed or stalled walk shows none either.
